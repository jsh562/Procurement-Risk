Stated plainly rather than quietly worked around.

1. **A-7 — `[COMPLETES FR-048]` on T058 cannot be added.** The task grammar in `.github/skills/artifact-conventions/SKILL.md` admits **one** `[COMPLETES req?]` marker per task line, and T058 already carries `[COMPLETES FR-039]`, which is correct — T058 is FR-039's completing task. ### Consequences the owner decisions did not anticipate

Recorded because the coordinator asked for them plainly rather than forced.

1. **A-6 removes FR-041's structural guarantee, and nothing can put it back inside this epic's boundary.** This is the one real cost and it is now **G-16**. The old cap was a partial unique index over member rows — "unrepresentable to violate", which is this data model's stated method. The new cap is "at most one *distinct* `specification_section` across a cluster's members", which is `count(DISTINCT …) <= 1` over a group, and PostgreSQL cannot express it: a `CHECK` sees one row; a partial *unique* index on `(resolved_entity_id, specification_section)` forbids two members **sharing** a value, the exact opposite of the rule; `EXCLUDE (resolved_entity_id WITH =, specification_section WITH <>)` would state it exactly and is unavailable because `<>` is not index-searchable in any access method, so it cannot be an exclusion operator; E009 adds zero triggers by declaration. The one route that works is a section column on **`resolved_entity`** pinned by a composite FK — a **sixth** column on an E003 table, which **G-11 already rules out in terms** ("exactly the widening this epic is already an exception for and should not compound"). **I did not take it**, because buying a constraint back by widening a governance exception is not a trade to make silently. Mitigations applied: the value is denormalized onto the member and pinned by `fk_rem__run_record_section` so the compared operand cannot lie, which keeps this an honest cross-row gap in the G-1/G-2 class; `ix_rem__entity_section` makes the admission check a single-table lookup; and **VR-019(b) asserts the cap by post-commit `count(DISTINCT …)` query rather than by expecting an exception** — a test that expected an error would pass against an implementation with no check at all, which is the trap this shape sets.
2. **A-6 undoes A-22's `SAVEPOINT`.** A-22 was fixed one pass earlier by adding a savepoint to `data-model.md` §Write Order step 8, and it existed *because* the refusal arrived as a unique violation that would otherwise abort the run's single transaction. With the cap moved to a pre-insert application check, no constraint fires and no statement fails, so the savepoint guards an exception that can no longer occur. Struck in place with the reason in §Write Order step 8, `plan.md` §Error Handling and `tasks.md` §Dependencies, rather than deleted — a recovery path left in the write order for an impossible exception reads as evidence the constraint still exists. **A-22 itself stays closed**: what it required was that §Write Order and §Error Handling stop disagreeing about a refused admission, and they now agree on the pre-check.
3. **A-6 makes `member_role` redundant, and swapping it out *narrows* the E003 crossing.** With no specification-section member, `member_role` was derivable from E003's delivered `member_kind` in both directions — which is exactly what `ck_rem__role_agrees_with_kind` asserted — so it carried no information. Replacing it with `specification_section` holds FR-045's added-column count at **five** and drops two checks, so `0505` adds **one object fewer** to `resolved_entity_member` than before. This is the only finding in either pass that reduced the governance exception rather than widening or merely documenting it, and P-6/AN-1's object lists are updated accordingly.
4. **A-2 needed two more columns fixed than the decision named, and the schema forces them.** Relaxing `…__census_declares_no_interval` and widening the reason domain makes VR-014's row *almost* writable — but `merge_precision` carries a registered `target_value` of 0.95, and `ck_resolution_figure__meets_iff_target` admits no NULL verdict beside a non-null target, so the row must declare `meets_target` — and then `ck_resolution_figure__cause_iff_shortfall` demands a cause for a `false`. I resolved it as `meets_target = false` with FR-032's three-part cause, which is **not** a workaround: an all-withheld run produced no evidence for the registered gate, so it did not meet it, and **SC-018 already takes exactly this position one figure over** ("where the run auto-merged nothing, published as the measured value with the shortfall and its cause per FR-032 rather than omitted"). Written into FR-028, SC-017, VR-014 and T055 so no implementer has to rediscover it. I verified all eighteen `resolution_figure` checks against the row; the other sixteen pass unchanged.
5. **A-6 leaves one thing genuinely weaker that I could not repair: SC-001 no longer has a schema-level backstop for the attribution's presence.** Under the member model, a specification member either existed as a row or did not. An attribution is the distinct value of a nullable column across members, and a run that dropped `specification_section` on the floor while populating everything else would produce clusters that satisfy every constraint and carry no attribution. `fk_rem__run_record_section` stops the value being *wrong* but cannot make it *present* — a NULL passes under `MATCH SIMPLE`, and it must, because purchase-order lines legitimately have none. So SC-001's attribution clause is graded by test only (VR-019(d), T047). I stated it in SC-001 explicitly — "an implementation that resolves the two members and exposes no section fails this criterion" — rather than leaving it to be inferred, but it is a test-level guarantee where the previous shape had a row-level one. It is the same class of exposure as G-16 and I have recorded it there rather than opening a seventeenth gap for one clause.

5. **A-39 — the recommendation is declined, and this is the one that matters.** The finding asks that the inline parenthetical revision history be moved out of the requirements into Clarifications and Stress-Test Findings, which own that content. **That is in direct conflict with six other findings in this same report.** A-9, A-10, A-12, A-13, A-32 and A-33 each require that superseded text be **struck in place with its reason** rather than relocated or deleted, precisely because the recurring failure in this document is a decision reversed in one place and left standing in another — and a supersession note moved away from the clause it supersedes is that failure by construction. Performing A-39 would also mean deleting or relocating roughly a third of the requirement text in a single pass, against artifacts three phases downstream already cite. **What was done instead**: a convention note at the head of § Functional Requirements declaring that the unparenthesised text is the requirement and a parenthetical note is never an obligation, so the reader cost the finding identifies is addressed without destroying the record. The obligation is left standing rather than closed. If the owner wants the wholesale move, it should be one deliberate pass with the supersession notes re-anchored by requirement id in Clarifications — not a side effect of this remediation.
